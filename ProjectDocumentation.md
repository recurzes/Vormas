# Project Documentation

## 1. Overview
The **VORMAS (Vehicle Rental Management System)** is a comprehensive desktop application designed to streamline the operations of a vehicle rental business. It handles the entire lifecycle of a rental, from fleet management and customer registration to reservations, rentals, returns, and billing.

## 2. System Objectives
- **Efficiency**: Automate manual tasks like availability checking and cost calculation.
- **Accuracy**: Reduce errors in billing and vehicle status tracking.
- **Control**: Provide role-based access (Admin vs. Rental Agent) to secure sensitive data.
- **Insight**: Offer a dashboard with key performance indicators (KPIs) for quick decision-making.

## 3. User Roles
- **Administrator**:
  - Full system access.
  - Manage users, fleet, rates, and configurations.
  - View all reports and logs.
- **Rental Agent**:
  - Front-desk operations.
  - Manage customers, reservations, rentals, and returns.
  - Process payments and view availability.
- **Customer** (Information only):
  - Customers are data entities; they do not log in to the WinForms app.

## 4. Feature List (Rental Agent)
1.  **Dashboard**: Quick view of active rentals, available vehicles, and pending returns.
2.  **Customer Management**: Register new customers, update details, view history.
3.  **Reservation Management**: Check availability, create/edit/cancel reservations.
4.  **Rental Processing**:
    - **Pickup**: Validate reservation, inspect vehicle, sign agreement.
    - **Return**: inspection, mileage check, damage recording, close rental.
5.  **Billing**: Generate invoices, calculate total fees (including penalties), process payments.
6.  **Vehicle Status View**: Check which vehicles are available, rented, or in maintenance.

## 5. System Workflow
1.  **Registration**: Customer is registered in the system.
2.  **Reservation**: Agent creates a reservation for specific dates and vehicle category/ID.
3.  **Rental (Pickup)**: On the start date, the reservation is converted to a Rental. Vehicle status $\rightarrow$ 'Rented'.
4.  **Return**: Customer returns vehicle. Agent records mileage/condition. Vehicle status $\rightarrow$ 'Available' (or 'Maintenance').
5.  **Billing**: System calculates final cost. Invoice is generated and paid.

## 6. Database Structure & ERD
*Reflecting the Core Entities:*

- **Users**: `Id`, `Username`, `PasswordHash`, `Role`.
- **Vehicles**: `Id`, `Make`, `Model`, `Year`, `Category`, `Status`, `LicensePlate`, `Mileage`.
- **Customers**: `Id`, `FirstName`, `LastName`, `Email`, `Phone`.
- **Reservations**: `Id`, `CustomerId`, `VehicleId`, `StartDate`, `EndDate`, `Status`.
- **Rentals**: `Id`, `ReservationId`, `VehicleId`, `CustomerId`, `StartDate`, `EndDate`, `StartMileage`, `EndMileage`.
- **Invoices**: `Id`, `RentalId`, `TotalAmount`, `IsPaid`.
